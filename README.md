# HEI Admin

An academic administration API for a three-year engineering curriculum: promotions and the tracks
they open, teaching groups, students and teachers, courses, exams, grades, and the diploma that
follows from all of it.

The HTTP contract lives in [`doc/api.yml`](doc/api.yml) and is the source of truth for it. This file
describes what the contract does not: the rules behind the endpoints, how the pieces fit, and how to
run the thing.

A browser interface ships alongside the API, under `/ui`, so the whole flow can be demonstrated
without a REST client.

## The domain

The curriculum is six semesters, 30 credits each, 180 in total.

- **S1 to S3 are common core.** Every student follows the same courses.
- **From S4 a student follows a track.** Two exist, `EL` (Software Ecosystem) and `TN` (Digital
  Transformation). A promotion decides which of them it opens; a track it leaves closed can be
  carried by no group and chosen by no student.
- **30 credits per semester means 30 per programme**, not 30 in the catalogue. From S4 the catalogue
  of a semester holds more than 30 credits, since it covers both tracks at once; each student still
  faces 30. A raw total above 30 on those semesters is expected, not a data error.
- **A student who has chosen no track for a semester is not failing it.** The result carries
  `TRACK_NOT_SELECTED`, which is a blocker with a cause, distinct from a semester genuinely missing
  credits. Nothing in the code treats it as a zero.
- **Grades are never overwritten silently.** Every change records its previous value, its new value,
  a reason type and a free-text reason. The first entry must be a `CREATION`; every later one must
  not be. Resubmitting the same value is refused.
- **Ranking allows ties.** Two graduates with the same average share a rank and the next one skips:
  1, 1, 3.

The semester table carries the common-core boundary **as data**, not as a constant in the business
code — see [`V44__seed_academic_reference_data.sql`](src/main/resources/db/migration/V44__seed_academic_reference_data.sql).
Moving the track choice to another semester, or opening a third track, is a row change and nothing
else.

## Architecture

Generated by POJA: a Spring Boot 3 application on Java 21, packaged for AWS Lambda behind SAM, with
PostgreSQL and Flyway.

```
endpoint/rest/controller   HTTP in, HTTP out. No business rule lives here.
endpoint/rest/security     authentication and authorization, all of it
endpoint/rest/mapper       REST model  <->  domain model
endpoint/ui                the Thymeleaf screens
endpoint/event             producing and consuming events
service                    the business rules
repository                 JPA entities and Spring Data repositories
file / mail                S3 and SES, POJA-generated
```

Packages group by responsibility, never one package per entity.

### The asynchronous path

Asking for a transcript renders the PDF and stores it on S3 within the request. What happens out of
band is the **delivery**: the caller gets a stored document and a link without waiting on a mail
server.

```
TranscriptService.request()
    renders the PDF, uploads it to S3, marks the request GENERATED
  → EventProducer  → EventBridge → SQS
  → EventConsumer  → EventServiceInvoker
  → TranscriptGeneratedService
      emails a time-limited presigned link to it, marks the request SENT
```

`EventServiceInvoker` resolves the handler **by reflection**: an event named `TranscriptGenerated`
is served by `com.exam.hei.service.event.TranscriptGeneratedService`. Adding an event means adding a
model and a service with the matching name — there is no registry to edit.

The request carries a status the caller can poll: `PENDING` → `GENERATED` → `SENT`, or `FAILED` with
a message saying which step gave way. The consumer stands down if the request is already `SENT`, so
a redelivered message does not send the transcript twice.

### Documents

- **Transcript PDF** — Thymeleaf in strict XML mode, rendered by Flying Saucer, stored on S3.
- **Graduate list Excel** — Apache POI, served by `GET /promotions/{id}/graduates/excel`.

## Security

Authentication is a JWT obtained from `POST /auth/login`.

- **API clients** send `Authorization: Bearer <token>`.
- **The browser** gets the same token in an `HttpOnly; Secure; SameSite=Strict` cookie, which is what
  makes a form-based interface possible without touching the REST path. The header wins when both
  are present.

Authorization lives entirely in `endpoint/rest/security` — `SecurityConf` for the path rules,
`StudentAuthorizer`, `TeacherAuthorizer` and `GradeAuthorizer` for the ones that depend on data. No
controller decides who may do what.

The rules that are not merely a matter of role:

- a student reads their own record, and only theirs
- a teacher reads the record of a student they teach, and no other. Their view of that student's
  grades is filtered to the courses they give, resolved against the group the student belonged to
  **on the day of the exam**
- a transcript belongs to its student alone: a teacher never reaches one, taught or not
- an administrator does the rest

CSRF protection is `SameSite=Strict` rather than a token: the cookie is not attached to
cross-site requests at all.

The first administrator is created at startup from `ADMIN_EMAIL` and `ADMIN_PASSWORD`, only when no
administrator exists, with a BCrypt-hashed password. It never fails startup and no migration carries
a credential.

### Accounts

An account is disabled, never deleted: `grade_history` names it as the author of every change it
carries.

`AuthProvider` resolves the signed-in account **from the database on every request** rather than
believing the claims of the token. Three consequences, all immediate rather than at the token's
twelve-hour expiry:

- a disabled account is refused from its very next call
- a change of role takes effect at once
- every token issued before the current password is refused

`POST /me/password` takes no identifier. The account is the one the token was issued for, so
changing somebody else's password cannot be expressed rather than merely being refused; the current
password is required besides. A reset performed by an administrator through `PUT /students` or
`PUT /teachers` closes the same sessions.

Disabling and enabling an account is `POST /students/{id}/deactivation` and its three siblings,
open to an administrator alone.

## The web interface

Sign in at `/ui/login`. Where you land depends on your role.

An administrator can run the whole demonstration from the browser, in this order:

| Screen | Route |
|---|---|
| Promotions and the tracks they open | `/ui/admin/promotions` |
| Teaching groups of a promotion | `/ui/admin/groups` |
| Students, their accounts, groups, track choices and account state | `/ui/admin/students` |
| Teachers, what they teach, and their account state | `/ui/admin/teachers` |
| Courses, filtered by semester | `/ui/admin/courses` |
| Exams of a course | `/ui/admin/courses/{id}/exams` |
| Grade entry and its change history | `/ui/admin/exams/{id}/grades` |
| Where a promotion stands, student by student | `/ui/admin/promotions/{id}/results` |
| Ranked graduates, and the Excel export | `/ui/graduates` |

A student opens `/ui/me`: their result, their applicable courses, their grades, and a button that
requests a transcript. A teacher opens the same route and sees what they teach. Both change their
password there, which signs them out of every session including that one.

Every screen calls the same services as the API and reports their refusals as messages on the form,
rather than letting a JSON payload reach someone filling in a field.

## Running it

**Java 21 is required.** Lombok does not run on JDK 26; if `compileJava` dies with
`ExceptionInInitializerError`, that is why.

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
```

Docker must be running — the integration tests start PostgreSQL and LocalStack containers.

```bash
sh gradlew test
```

```bash
sh gradlew build
```

Format before committing:

```bash
./format.sh
```

There is no `application.yml` in the repository. Configuration is environment-driven and set in the
POJA console; the datasource, the bucket, the event bus and the SES region all come from there.
Only `ADMIN_EMAIL`, `ADMIN_PASSWORD` and `JWT_SECRET` are read by code in this repository.

Dependencies are declared through the POJA console's custom-dependency mechanism, never by editing
`build.gradle` by hand.

## Tests

83 test classes — 54 integration, 29 unit. The suite runs 817 tests and holds line coverage at 96%,
against a floor of **80% enforced by the build**: `jacocoTestCoverageVerification` fails it below
that.

Integration tests share one PostgreSQL container across classes (`FacadeIT`) and run on half the
available cores in parallel.

**S3 is tested for real, against LocalStack, never against the AWS account.**
`BucketComponentLocalStackIT` exercises the actual `BucketComponent` with static credentials, so the
default credentials chain is never consulted and no test can reach a real bucket. Everywhere else
that would touch AWS, the client is mocked.

Authorization is proved in HTTP, not in markup. `TeacherScopeIT`, `AccountLifecycleIT`,
`PasswordChangeIT` and `AuthorizationMatrixIT` assert the status codes each role actually receives,
so a screen that hides a button is never mistaken for an endpoint that refuses one.

## Known limits

These are real and deliberately not papered over.

- **Transcript emails end `FAILED` in the deployment.** The SES sender is `@Value("noreply@poja.io")`
  in the POJA-generated `EmailConf` — a literal, not a property placeholder — so no environment
  variable can change it, and the account is in the SES sandbox besides. The asynchronous pipeline
  itself is implemented and tested; only the delivery fails.
- **`PromotionService` does not check that `start_year` precedes `end_year`.** A promotion running
  2028 to 2025 is accepted.

## POJA-generated files

Classes annotated `@PojaGenerated` are regenerated by the platform and are not edited here. Where one
needed different behaviour, it was subclassed or overridden from outside instead — see
`BucketComponentLocalStackIT`, which supplies its own bucket configuration without touching the
generated `BucketConf`.
